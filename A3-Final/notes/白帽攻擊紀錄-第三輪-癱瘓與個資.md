# 白帽攻擊紀錄（第三輪）：癱瘓與偷個資

日期：2026-11-03。對象：commit 5720166 之後的程式。環境：本機模擬 FHIR Server（:8090）＋模擬 Gemini，不碰公開伺服器。
這一輪不重打前兩輪已經試過的項目（限流繞過、超大 body、慢伺服器、翻頁迴圈、去識別化、證據檔遮罩、XSS），只補前兩輪沒做的。

結果欄：**發現** = 有問題已修；**守住** = 原本就擋住；**接受** = 不改，原因寫在說明。

## L. 癱瘓（可用性）

| # | 攻擊 | 結果 | 說明 |
|---|---|---|---|
| L1 | 對 `/api/twcore/validate` 連打 61 次 | **發現** | 建立類端點原本沒限流，每一次都會轉成對共用 FHIR Server 的請求，等於拿我們當跳板打別人。新增 `services/rateLimit.js`，寫入類（POST／PUT）每個 IP 每分鐘 120 次（按一次「建立」約 10 次請求），第 121 次起 429 |
| L2 | 對 CDS `/cds-services/patient-triage-service` 連打 61 次 | **發現** | 同上，每次都會查 FHIR Server。每分鐘 60 次，第 61 次起 429 |
| L3 | 讀取端點（`GET /api/twcore/patient/:id`）連打 70 次 | 接受 | 不限流：醫師頁會自動讀，讀取不會改資料；壞處是仍可拿來查流量，列入已知風險 |
| L4 | 病人回報送 11 次（其中空白內容） | 守住 | 第 11 次 429；改成中介層後**空白等無效請求也算次數**，攻擊者不能用無效請求探路 |
| L5 | 限流表記憶體：換幾百個來源 IP 之後表會不會一直長 | **發現** | 原本 `Map` 只加不刪。改成每個時間窗清一次過期 IP，計時器 `unref()` 不擋程式結束 |
| L6 | 5000 層巢狀 JSON、陣列當 body、數字當 body | 守住 | 100 KB 上限先擋，剩下的進到欄位檢查回 400，位置指到 `Organization.identifier` |
| L7 | 幾百條慢速連線（slowloris） | 未測 | Node 預設 `headersTimeout` 60 秒會自己斷，但沒有實際打；本專案只聽 127.0.0.1，影響範圍是本機 |

## M. 偷個資（機密性）

| # | 檢查 | 結果 | 說明 |
|---|---|---|---|
| M1 | 壞 JSON、超大 body、型別錯、`%00%ff` 當 id、CDS 缺 context：回應裡有沒有堆疊、`node:internal`、`/Users/…` 路徑 | 守住 | 五種回應都只有一句中文（或 Express 的一句英文），沒有堆疊與路徑；500 一律「伺服器內部錯誤」，細節只印在後端終端機 |
| M2 | 終端機紀錄（`screenshots/app/後端終端機紀錄.txt`）有沒有金鑰、token、身分證 | 守住 | 0 筆；查詢參數值一律 `…` |
| M3 | 證據檔 `logs/fhir-exchange.jsonl` | 接受 | **明文含姓名與身分證**，這是聯測 Monitor 要的 Request／Response 證據，刻意保留；`logs/` 不進版控、不進測試包，只能用假資料 |
| M4 | 讀取端點沒有認證 | 接受 | 知道 Patient ID 就能經後端讀病人；後端只聽 127.0.0.1，而且公開測試伺服器本身就不需認證。真的上線要在前面加 SMART／OAuth（決策 D17 的 token 目前只用在後端→FHIR Server 這一段） |

- 使用者情境 28／28、完整流程 22 步截圖全部重拍（`screenshots/app/`）。
- 改動：`services/rateLimit.js`（新）、`routes/triage.js`（改用共用模組）、`routes/twcore.js`（寫入限流）、`routes/cds-hooks.js`（限流）。
