# 白帽攻擊紀錄（第二輪）：照 2026 台灣聯測松的標準打

日期：2026-10-31。攻擊對象：commit ef74fbc 之後的程式。環境：本機模擬 FHIR Server（:8090）、模擬 Gemini、另寫一台「壞掉的 FHIR Server」（:8091，15 種行為）。
聯測松規則來源：官網擷取檔 `Final/notes/twcat/摘要.md`。本輪依它的三個重點設計攻擊：

1. **Monitor 看的是 Request／Response 證據**：所以攻擊證據檔與終端機紀錄能不能被偽造、能不能把失敗顯示成成功。
2. **資源要通過 Validator（Error 0）**：所以攻擊送出的 JSON 會不會被塞進不合法的內容。
3. **對方（Server）可能行為怪異**：所以模擬對方回 HTML、空 body、轉址、翻頁迴圈等，看 Client 會不會被牽著走。

結果欄：**發現** = 有問題已修；**守住** = 原本就擋住；**接受** = 不是問題或刻意不改。

## K. 壞掉的 FHIR Server（15 種行為，`/tmp/a3scripts/evilfhir.js`）

| 伺服器行為 | 修正前 | 修正後 |
|---|---|---|
| 回 HTML／XML（例如被導到登入頁） | 畫面顯示 **✓ 已建立 HTTP 200** | 502「回應不是 Organization 資源，無法確認有沒有建立成功」 |
| 201 但沒 body | ✓ 已建立，ID 空的 | 同上 |
| 201 但 body 是 Bundle／id 帶 `<script>` | ✓ 已建立 | 同上（id 要符合 FHIR id 規則） |
| 200 ＋ OperationOutcome（其實失敗） | 守住（$validate 先擋） | 422 |
| 搜尋結果第一筆是 OperationOutcome（HAPI 有警告時會這樣） | 被當成「已存在」，PUT 到 `Organization/undefined` | 只認 `resourceType` 相符的那筆 |
| 翻頁 next 指到別台／別路徑 | 只比對字串開頭 | 比對 `origin` 完全相同才跟 |
| 翻頁永遠有 next | 守住（最多 10 頁） | 另加 id 去重、最多 500 筆、`truncated` 旗標 |
| 一頁回 5000 筆 | 全部吐給畫面 | 最多 500 筆 |
| 25 秒才回／永不回 | 守住（20 秒逾時 → 502） | — |
| 302 轉址到別的主機 | axios 跟著跳 | `maxRedirects: 0`，回報「HTTP 302」 |
| $validate 回 200 但 error／回 500 | 守住 | 422／500 |
| 讀病人回 HTML | 當成「病人存在」，**花了 AI 額度**才失敗 | 先確認 `resourceType === 'Patient'` |
| CDS 查 Observation 回 HTML／OperationOutcome | 卡片顯示「**尚無 AI 分流紀錄**」（把壞掉說成沒事） | 502「FHIR 查詢失敗，無法產生分流建議」 |
| 別隊的病人資料：名字是 `<img onerror>`、5000 字、物件、null | 守住 | Vue 自動跳脫；`nameOf()` 只認字串 |
| 別隊的 Observation：note 含 Markdown 圖片／javascript: 連結 | 守住 | 卡片 detail 把 `[ ] ( ) < > ` 等跳脫 |
