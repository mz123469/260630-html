# AI 分流系統：測試指南（Windows／macOS）

給測試工程師用。照順序做完約 20 分鐘，每一項都附預期畫面（測試包裡的 `截圖/`；原始檔在 `Final/screenshots/app/`）。
**只能用虛構資料。** 系統會把資料寫到共用的 TW Core 測試伺服器 `https://twcore.hapi.fhir.tw/fhir`。

## 1. 準備

| 項目 | 需求 |
|---|---|
| Node.js | 20.19 以上或 22.12 以上（`node -v` 檢查）。下載：<https://nodejs.org/> |
| 網路 | 要連得到 `twcore.hapi.fhir.tw` 與 `generativelanguage.googleapis.com` |
| Gemini API Key | 自己申請（<https://aistudio.google.com/>），第一次啟動時填進 `AI-Patient-Triage-System/.env` |
| Java 17 以上 | 第 5 節「官方驗證器」與 G 節「匯入聯測 JSON」的驗證、上傳需要（先跑一次 `tools/validate.sh` 下載 validator_cli.jar；後端找不到 Java 時在 `.env` 設 `JAVA_HOME`） |
| 瀏覽器 | Chrome、Edge、Safari 最新版 |

## 2. 啟動

| 系統 | 怎麼做 |
|---|---|
| macOS | 雙擊 `start-mac.command`。第一次若出現「無法打開」，按右鍵 →「打開」；或在終端機執行 `bash start-mac.command` |
| Windows | 雙擊 `start-windows.bat` |

第一次執行會建立 `.env` 並打開它：填入 `GEMINI_API_KEY`、存檔，再執行一次。
成功後瀏覽器會自動打開 <http://localhost:5173/setup>（聯測順序模式）。導覽列最左邊可切換「一般使用｜聯測順序」，第 3 節 A–E 是聯測順序，F 是一般使用。
後端視窗會印出 `Server is running on http://localhost:3000` 和 `FHIR Server: https://twcore.hapi.fhir.tw/fhir`。

> 啟動腳本會先檢查 3000、5173 埠。被占用時會顯示「埠 … 已被占用」並停下，先關掉上次沒關的程式再執行。前端固定用 5173，不會自動換埠。

手動啟動（不用腳本）：開兩個終端機，
`cd AI-Patient-Triage-System && npm install && node server.js`，以及
`cd Client && npm install && npm run dev`。

## 5. 官方驗證器（TW Core IG 1.0.0）

需要 Java 17 以上（`java -version` 檢查）。

| 系統 | 指令（在本資料夾） |
|---|---|
| macOS | `node tools/export-examples.js && cd tools && ./validate.sh` |
| Windows | `node tools\export-examples.js`，再把 `tools\examples` 裡的 json 拖到 `tools\validate.bat` |

預期：12 個檔 **Error 0**（含聯測匯入範例 `Bundle-fhirfox-import-example.json`）；只有 Observation 一則 Warning（UCUM `{score}` 註解單位）。報告在 `tools/validation-report.html`。

## 6. 已知事項

- 測試伺服器上的 TW Core 是 **0.3.2**；建立前的伺服器驗證照 0.3.2。對 1.0.0 的驗證請用第 5 節。
- 機構只能從 TW Core 官方 50 家清單選，共用伺服器上多半已有人建過，所以常會問「更新這筆」。**按更新會改到那筆共用資料**，測試時請留意。
- 「重新開始」只清這台瀏覽器的狀態，不刪伺服器資料。
- 匯入：測試伺服器跑 TW Core 0.3.x，PractitionerRole 的 `specialtyCode`（官方 Spec-0001，SNOMED）會讓整包被拒（422，整包都不寫入）；範例因此沒有帶。就醫、診斷、檢驗等每上傳一次就多一份。
- `截圖/` 是在模擬 FHIR Server 與模擬 Gemini 上拍的，畫面與流程相同，ID 與分數會跟實測不同。
